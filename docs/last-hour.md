# 最後の1時間

競技終了の1時間前から、新しい改善を止めて、提出できる状態にする。

## 1時間前
1. 改善の受け入れを締め切る。以降はバグ修正と提出準備だけにする
2. 採用するブランチを1つに決め、mainに統合する。`make try`でpassとスコアを確認する
3. 試して効果のなかった変更や、不安定な変更を外す

## 45分前: 設定の後始末
1. スロークエリログを無効にする(`slow_query_log=0`、またはconfigs/mysql/10-slowlog.cnfを外す)
2. nginxのアクセスログを、LTSVからオフ、または通常の出力に戻す
3. pprofの組み込みと、デバッグ出力を外す
4. 計測用に入れたツールのcronや常駐がないか確認する
5. 外した状態で、もう一度`make try`を回す。計測設定を外した後のスコアが、提出スコアの目安になる

## 30分前: 再起動試験
1. 全サーバをrebootする
2. アプリ、nginx、MySQLなど、必要なサービスが自動で起動することを確認する(`systemctl is-active`、`ss -ltnp`)
3. rebootの後は何も触らず、ベンチを回す。passになることと、スコアが直前と大きく違わないことを確認する
4. 起動しないものがあれば、`systemctl enable`を確認する。手動で起動した設定がないか見直す
5. 2台以上の場合は、起動順の依存(DBが先に立つかなど)も見る

## 15分前
1. 最終の状態を、ブランチとコミットで記録する
2. 以降のデプロイをやめる。リースを他の人が取らないように、担当を1人にする
3. 本番の提出手順(ポータルのベンチ、最終計測)を、レギュレーションで再確認する

## 終了後
- 自前の練習環境は削除する。本番の環境は何もしない
