# N+1の解消

## 検出
- slow.txtで同じ形のクエリが数万回呼ばれていればN+1
- alpで1リクエストあたりの時間が長いエンドポイントを選び、ハンドラ内のループ内クエリを探す

## 解消パターン
1. JOINにまとめる。private-isuでは投稿とユーザーのJOINで大きく伸びた記録がある
2. IN句でまとめて取得し、アプリ側でmapにして引く
3. memcachedの複数キー取得(get_multi)を使う。キーを先に配列で作ってからまとめて取る
4. 更新されないマスタ的な表はアプリ起動時に読み込んでグローバル変数に持つ
5. 集計を読み出し時に計算せず、イベント発生時にカウンタを加算する

## 落とし穴
- ウィンドウ関数でまとめる方法は、DBのバージョン差で動作が違った例がある(MariaDBでは動くがMySQL 8では動かない)
- 参照だけのリクエストのトランザクションは外せることが多い
- 関数がネストしていて追いにくい場合は、先にmemcachedで逃がす方針も検討する
